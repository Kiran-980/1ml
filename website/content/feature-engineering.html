Feature engineering and preprocessing skills.

Use 1ml with Codex or Claude Code to prepare tabular data, handle missing values and categories, and review scikit-learn pipelines for data leakage.

Start with what is known at prediction time

A feature can improve a notebook score and still be unusable. A refund recorded after cancellation cannot help predict that cancellation in advance. An average calculated over a customer's entire history may accidentally include future activity.

The prepare skill connects source semantics, feature availability, model requirements and the evaluation design. Ask it to distinguish a proposed feature from a measured improvement. Keeping the existing representation is a valid outcome.

Review a tabular preprocessing pipeline

Use 1ml's prepare skill to review preprocessing for my churn classifier. The raw inputs include numeric usage, categorical plan names and missing account fields. Predictions happen at the start of each month. Check which source values are available then. For a scikit-learn pipeline, specify which operations are fixed and which learn from data; fit learned operations within each training fold. Test unseen categories, missing markers, row alignment and the raw input schema at inference. Show a bounded raw-to-processed example and explain any additional features you retain.

Choose transformations for the candidate

DecisionWhat to check
Missing valuesDistinguish unknown from not applicable. Inspect relevant missingness patterns before choosing imputation or native missing-value support.
Scaling and encodingMatch numerical scales and categorical representations to the estimator. Check how unseen categories are handled.
Feature selectionFit data-dependent selection inside training folds and compare candidates under the same validation design.
Lagged or aggregate featuresUse only observations available at the prediction timestamp and preserve entity boundaries.

Keep learned preprocessing inside cross-validation

Learned imputers, scalers, vocabularies and selectors must respect the training boundary. Fitting them on the full dataset before cross-validation leaks information into validation. A reusable pipeline helps apply the same fitted transformations when predicting, but the pipeline still needs the right split and input schema.

Ask for an observed fit-and-transform check using the raw columns the deployed prediction code will receive. Check the resulting feature names or shape, accepted missing values and unknown-category behavior. This catches errors such as applying a transformation twice or dropping a column before another step uses it.

For a worked task prompt, continue to classification, regression or time series forecasting. For unresolved source patterns, return to exploratory data analysis.
